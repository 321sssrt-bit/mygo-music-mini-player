# 采用绑定系统媒体会话的伴生进程实现迷你悬浮窗

`egoist/mygo-music` 的插件运行在隔离的 JS 沙盒中，仅建模音源曲库接口（`music.Source`），不提供创建原生窗口、读取全局跨音源播放状态或联动主窗口显隐的扩展点；若改为直接给宿主源码打补丁（如替换主程序可执行文件），每次上游发版都会失效并需要重新移植。因此我们决定采用标准插件加 `host.spawn` 原生伴生进程（基于 `egoist/mygo`）的架构，并严格只绑定 `mygo-music` 进程发布的系统媒体会话（Windows SMTC / Linux MPRIS）同步封面、进度与播控。

## Considered Options

- **原版插件 + `host.spawn` 原生伴生进程 + 系统媒体会话（已选）**：零侵入原版宿主，兼容官方自动更新及任意第三方音源插件。
- **宿主源码补丁 / Fork**：可拿到内部队列随机/循环与红心状态，但破坏原版升级体验且维护成本高。

## Consequences

- 原版宿主未向系统媒体会话暴露「红心喜欢」与「队列随机/循环模式」，展开态不再保留这两个槽位，而是按 `mygo-music` 原生设计语言重新设计布局。
- 明确暂不支持 macOS（macOS 版 `mygo-music` 已内置顶部 Notch Player，且 macOS 15.4+ 限制未授权第三方进程读取系统 `MediaRemote` 播放信息），在文档与界面中注明原因。
